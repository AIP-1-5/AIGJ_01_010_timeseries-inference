# 🧭 5. 과제 5 상태 판단: 사용 여부와 환기 경보

센서 값을 보고 "지금 방에 사람이 있나?"와 "30분 안에 환기가 필요해지나?"를 예/아니오로 답하는 과제입니다. 숫자를 맞히는 예측(과제 3)과 달리, 정해진 칸 중 하나를 고르는 **분류** 문제입니다.

> 📖 읽는 순서: 1부(요약 → 비유 → 용어 → 분류와 회귀 → 특징 → 모델 → 정답의 문제 → 평가 지표 → A 사용 여부 결과 → B 환기 경보 결과 → 내 데이터) → 2부(코드) → 자주 하는 실수 → 예상 질문

# 1부. 처음 보는 사람을 위한 설명

## 1. 한 문장으로 요약하면

> 센서 값만으로 만든 특징을 HistGradientBoosting 분류기에 넣어, **사용 여부**는 직접 관찰 6일 기준 F1 85.8(단순 규칙 79.1)을, **환기 선제 경보**(30분 안 1,000ppm 초과)는 재현율 97.4%, macro-F1 96.7(규칙 81.5)을 얻었습니다. 내 실습실 데이터에서는 소음 센서로 만든 대리 정답 기준 정확도 89.8%(규칙 73.7%)였고, 환기 경보는 이 기간 1,000ppm 을 넘은 적이 없어 양성 사례가 0건이었습니다.

| "감기냐 아니냐" 고르기 | 사용중/비어있음, 경보/경보 없음 | 분류 (classification) |

| 의사의 판단 경험 | 학습한 분류 모델 | HistGradientBoosting |
| 진료 기록상의 진단명 | 일정(수업·예약)으로 만든 정답 | 학습 정답 (label) |
| 진료 기록이 실제와 다를 때 | 결석·노쇼·연장·예약 없는 사용 | 정답의 잡음 |

| 다른 검사 결과로 대신 확인 | 소음 센서 LAeq 로 만든 정답 | 대리 정답 (proxy label) |

## 3. 용어 사전

| 용어 | 쉬운 뜻 | 이 과제에서는 |
| --- | --- | --- |
| 분류 | 정해진 칸 중 하나를 고르기 | 0(비어있음/경보 없음) 또는 1(사용중/곧 환기 필요) |
| 회귀 | 숫자 자체를 맞히기 | 과제 3 의 CO₂ 예측 |
| 특징 (feature) | 모델에 넣는 입력 숫자들 | `state_features` 가 만드는 열들 |
| 변화량 | 지금 값 − 몇 칸 전 값 | 5·15·30분 CO₂·온도·습도 변화 |
| 원-핫 (one-hot) | 여러 칸 중 해당하는 칸만 1 | 공간 번호를 sp0~sp3 열로 |
| 결정 트리 | 예/아니오 질문을 이어 가는 판단 나무 | "CO₂ 15분 변화 > 20?" 같은 질문들 |
| 부스팅 (boosting) | 작은 나무를 여러 개 차례로 만들며 앞의 실수를 고침 | 사용 여부 300개, 환기 400개 반복 |
| 정답 (label) | 모델이 배울 "맞는 답" | 학습은 일정, 평가는 직접 관찰 |
| 혼동 행렬 | 맞음/틀림을 4칸으로 나눈 표 | 실제 × 예측 |
| 정확도 (accuracy) | 전체 중 맞힌 비율 | 불균형일 때는 믿기 어려움 |
| 재현율 (recall) | 실제 1 중 1이라고 맞힌 비율 | 환기 경보 97.4% |
| 정밀도 (precision) | 1이라고 한 것 중 진짜 1 비율 | 환기 경보 90.1% |
| F1 | 재현율과 정밀도를 함께 본 점수 | 사용 여부 85.8 |
| macro-F1 | 0 칸과 1 칸의 F1 을 각각 구해 평균 | 환기 경보 96.7 |
| 양성 (positive) | 우리가 찾고 싶은 쪽(1) | 지금 1,000 미만인데 30분 안에 1,000 이상 |
| 클래스 불균형 | 한쪽이 훨씬 많음 | 환기 양성 3.3% |
| 임계값 | 확률이 몇 이상이면 1로 볼지 | 환기 경보 0.91 |
| 대리 정답 | 진짜 정답 대신 쓸 만한 다른 신호 | 소음 센서 LAeq ≥ 34.5dB |

## 4. 분류와 회귀는 무엇이 다른가

1. **회귀**는 "몇 ppm 이 될까?"처럼 숫자를 맞힙니다. 과제 3 이 회귀입니다. 평가도 "몇 ppm 틀렸나(MAE)"로 합니다.
2. **분류**는 "사람이 있나 없나?"처럼 정해진 답 중 하나를 고릅니다. 평가는 "몇 번 맞혔나, 무엇을 놓쳤나"로 합니다.
3. 분류 모델은 보통 "1일 확률"을 내고, 그 확률이 임계값 이상이면 1로 판단합니다. 사용 여부는 0.5, 환기 경보는 0.91 을 썼습니다.
4. 환기 경보는 회귀로도 풀 수 있습니다("30분 뒤 예측값 ≥ 1,000"). 하지만 회귀는 값 전체를 맞히려다 경계 근처 판단에 둔할 수 있고, 분류기는 "넘느냐 안 넘느냐"에만 집중해 경계를 더 잘 가릅니다.

## 5. 특징: 모델이 보는 입력

`state_features` 함수가 센서 값만으로 다음을 만듭니다(5분 칸 기준).

| 특징 | 뜻 | 왜 필요한가 |
| --- | --- | --- |
| `co2` | 지금 CO₂ | 사람이 많으면 높음 |
| `dco2_1/3/6` | 5·15·30분 CO₂ 변화량 | 사람이 들어오면 오르기 시작 |
| `dtemp_1/3/6`, `dhum_1/3/6` | 온도·습도 변화량 | 사람 체온·호흡으로 조금 오름 |
| `co2_above_min6h` | 최근 6시간 최저 CO₂ 대비 지금 | 방마다 바닥값이 달라서 "평소보다 얼마나 높은지" |
| `hs, hc` | 시각을 원 위의 점으로(사인·코사인) | 23시와 0시가 가깝다는 것을 알게 함 |
| `ds, dc` | 요일을 원 위의 점으로 | 요일 패턴 |
| `we` | 주말이면 1 | 주말엔 거의 비어 있음 |
| `sp0~sp3` | 공간 원-핫 | 공간마다 크기가 달라 CO₂ 오르는 정도가 다름 |

- **사용 여부에는 일정 정보를 넣지 않습니다.** 정답을 일정으로 만들었는데 입력에도 일정을 넣으면, 모델이 센서를 안 보고 일정을 베껴 학습 정답과 거의 100% 맞는 척만 합니다. 그러면 노쇼·예약 없는 사용 같은 진짜 차이는 하나도 못 잡습니다.
- **환기 경보에는 앞으로의 일정 인원(`plan_0/1/3/6`)을 넣습니다.** 환기 경보 정답은 일정이 아니라 실제 CO₂ 값에서 만들어지므로 베낄 위험이 없습니다.

## 6. HistGradientBoosting 을 쉬운 말로

1. **결정 트리**: "CO₂ 15분 변화가 20ppm 넘나? → 예 → 최근 6시간 최저보다 150 넘게 높나? → 예 → 사용중" 같은 질문 사다리입니다.
2. 나무 하나는 단순해서 자주 틀립니다.
3. **부스팅**: 첫 나무가 틀린 부분을 두 번째 나무가 고치고, 그래도 틀린 부분을 세 번째가 고칩니다. 이것을 수백 번(사용 여부 300번, 환기 400번) 반복합니다. 스무고개를 여러 사람이 이어서 하며 앞사람 실수를 보완하는 것과 비슷합니다.
4. **Hist(히스토그램)**: 숫자를 미리 구간(칸)으로 나눠 두고 질문을 찾기 때문에 빠릅니다.
5. **`class_weight="balanced"`**: 적은 쪽(양성)을 틀리면 벌점을 더 크게 줘서, 많은 쪽만 외우지 않게 합니다.
6. 표 형태 숫자 데이터에 강하고, 작고 빨라서 보드에서 매분 돌리기에도 부담이 없습니다. 결측값도 스스로 처리합니다.

## 7. 정답을 어디서 가져오나: 일정 정답과 그 한계

1. 학습하려면 "이 시각에 사람이 있었다/없었다" 정답이 많이 필요합니다.
2. 사람이 매분 기록할 수는 없으니 **일정(수업 시간표·회의실 예약)** 으로 정답을 만들었습니다. 일정이 있으면 사용중, 없으면 비어있음입니다.
3. 하지만 일정은 실제와 다릅니다. 결석, 예약 노쇼, 수업 연장, 예약 없이 쓰는 경우가 있습니다.
4. 그래서 **평가는 직접 관찰한 6일(8~19시)** 로 했습니다.
5. 일정 정답이 직접 관찰과 일치한 비율은 **89.7%** 였습니다(빈 방인데 일정상 사용중인 비율 1.5%). 즉 학습 정답 자체가 약 10% 틀려 있습니다.
6. **라운지**는 일정이 아예 없어서 일정 정답이 늘 "비어있음"입니다. 학습에 넣으면 "라운지는 늘 빈 방"을 배워 버립니다. 그래서 학습에서 빼고 "처음 보는 공간"으로 평가했습니다.

> 🎤 **Q. 정답이 10%나 틀린데 모델을 믿을 수 있나요?**
> 학습 정답(일정)은 직접 관찰과 89.7%만 일치합니다. 그래도 모델은 센서만 보기 때문에, 일정이 틀린 순간(노쇼·예약 없는 사용)에도 실제 CO₂ 변화를 보고 판단할 수 있습니다. 실제로 직접 관찰 기준 재현율이 일정 정답은 75.7%인데 모델은 84.9%로 더 높았습니다. 평가는 반드시 일정이 아닌 직접 관찰로 했기 때문에 이 숫자는 믿을 수 있습니다.

## 8. 평가 지표: 정확도만 보면 안 되는 이유

혼동 행렬의 네 칸:

| 실제 \ 예측 | 0 (아니오) | 1 (예) |
| --- | --- | --- |
| 0 (아니오) | 맞게 아니오 (TN) | 헛경보 (FP) |
| 1 (예) | 놓침 (FN) | 맞게 예 (TP) |

- **정확도** = (TN + TP) ÷ 전체
- **재현율** = TP ÷ (TP + FN) → "진짜를 얼마나 놓치지 않았나"
- **정밀도** = TP ÷ (TP + FP) → "울린 경보가 얼마나 믿을 만한가"
- **F1** = 재현율과 정밀도의 조화 평균. 둘 중 하나만 높으면 낮게 나옵니다.
- **macro-F1** = 0 쪽 F1 과 1 쪽 F1 의 평균. 적은 쪽을 무시하면 크게 떨어집니다.
- 환기 경보는 양성이 3.3%뿐이라 **"항상 경보 없음"만 해도 정확도 97.1%** 입니다. 하지만 재현율 0, F1 0, macro-F1 49.3 입니다. 그래서 정확도가 아니라 재현율·정밀도·macro-F1 로 판단했습니다.

## 9. A. 사용 여부 결과 (합성 데이터, 직접 관찰 6일 기준)

| 방법 | 정확도 | F1 | macro-F1 | 재현율 | 정밀도 | 빈 방→사용중 오판율 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 일정 기반 정답 (참고) | 89.7 | 85 | 88.6 | 75.7 | 96.9 | 1.5 |
| 단순 규칙 (15분 CO₂ +30ppm) | 86.5 | 79.1 | 84.6 | 66.6 | 97.5 | 1.1 |
| **분류 모델 (센서만)** | **89.1** | **85.8** | **88.5** | **84.9** | 86.6 | 8.2 |

혼동 행렬 (분류 모델):

| 실제 \ 예측 | 비어있음 | 사용중 |
| --- | ---: | ---: |
| 비어있음 | 1787 | 160 |
| 사용중 | 184 | 1037 |

공간별:

| 공간 | 정확도 | F1 | 빈 방→사용중 오판율 |
| --- | ---: | ---: | ---: |
| 강의실1 | 87.4 | 90.5 | 1.8 |
| 강의실2 | 94.7 | 90.9 | 0.6 |
| 회의실 | 85.6 | 80.9 | 19 |
| 라운지 (학습 안 함) | 88.9 | 71.8 | 7.9 |

가장 많이 틀리는 상황:

| 상황 | 샘플 수 | 오류율(%) |
| --- | ---: | ---: |
| 퇴실 후 20분 이내 (실제 빈 방) | 280 | 15 |
| 입실 후 15분 이내 (실제 사용중) | 210 | 19.5 |
| 그 외 | 2705 | 9.9 |

해석:
1. 모델은 F1 85.8 로 단순 규칙 79.1 보다 높습니다. 특히 재현율이 66.6 → 84.9 로 크게 좋아졌습니다. 규칙은 "CO₂ 가 오르는 중"일 때만 사용중이라 해서, 사람이 있어도 CO₂ 가 평탄하면 놓칩니다.
2. 대신 정밀도는 규칙(97.5)보다 낮은 86.6 입니다. 모델이 "사용중"을 더 적극적으로 말하는 대신 가끔 빈 방을 사용중으로 봅니다.
3. **퇴실 직후**: 사람이 나가도 CO₂ 는 환기 속도만큼 천천히 내려가 한동안 "사람 있던 수준"에 머뭅니다.
4. **입실 직후**: CO₂ 가 오르기 시작하는 데 몇 분이 걸립니다(센서 반응 지연 + 5분 평균).
5. 큰 강의실에 적은 인원이면 CO₂ 변화가 작아 구별이 어렵고, 작은 회의실은 2~3명도 잘 보입니다.
6. 라운지는 학습에 없던 공간인데도 정확도 88.9%, F1 71.8 이었습니다.
7. 냉난방 자동 제어에 쓴다면 "끄는 결정"은 "비어있음"이 15분 이상 이어질 때만 내리는 것이 안전합니다. 사람이 있는데 끄는 불편이 더 크기 때문입니다.

> 🎤 **Q. 회의실 오판율이 19%나 되는 이유는?**
> 회의실은 작아서 사람이 나간 뒤에도 CO₂ 가 한동안 높게 남고, 짧은 회의가 자주 있어 입실·퇴실 직후 구간이 많습니다. 모델이 가장 많이 틀리는 때가 바로 퇴실 후 20분(오류 15%)과 입실 후 15분(오류 19.5%)입니다. 그래서 회의실은 빈 방을 사용중으로 보는 비율이 19%로 가장 높았습니다. 자동 제어에 쓴다면 "비어있음"이 15분 이상 이어질 때만 끄는 식으로 보완합니다.

## 10. B. 환기 선제 경보 결과 (합성 데이터 5주차)

정의와 규칙:
1. **양성**: 지금 CO₂ < 1,000ppm 이고, 앞으로 30분(6칸) 안에 1,000ppm 이상이 되는 시점입니다. 양성 비율은 3.3%입니다.
2. **이미 넘은 시점은 뺍니다.** 넣으면 "지금 1,000 이상이면 경보"만 배워도 점수가 오르지만, 그건 "미리" 알리는 게 아니라 이미 늦은 경보입니다.
3. 고장 구간(앞 30분~뒤 60분)도 뺍니다.
4. **임계값 0.91**: 검증 주에서 재현율 90% 이상을 지키는 가장 높은 확률 기준입니다. 높을수록 헛경보가 줄어서, 기준을 지키는 한 가장 높게 잡았습니다.

해석:
- 양성 196건 중 191건을 미리 잡았습니다(재현율 97.4%, 기준 85% 이상 충족). 놓친 것은 5건입니다.

- macro-F1 96.7 로 단순 규칙 81.5 보다 높습니다.
- 환기를 늦추는 비용(졸림·두통)이 헛경보로 창문을 한 번 여는 비용보다 크므로 **재현율을 우선**했습니다. 대신 같은 공간에 15분 안에 다시 울리지 않게 묶어 체감 헛경보를 줄입니다.

def state_features(gs: pd.DataFrame, si: int, n_spaces: int) -> pd.DataFrame:
    """센서값만으로 만든 특징 (일정 정보 없음). gs: time × [co2, temperature, humidity]"""
    c, t, h = gs["co2"], gs["temperature"], gs["humidity"]
    f = pd.DataFrame(index=gs.index)
    f["co2"] = c                              # ← 지금 CO₂
    for k in (1, 3, 6):                       # 5·15·30분 변화량
        f[f"dco2_{k}"] = c - c.shift(k)       # ← k칸 전과의 차이
        f[f"dtemp_{k}"] = t - t.shift(k)
        f[f"dhum_{k}"] = h - h.shift(k)
    f["co2_above_min6h"] = c - c.rolling(72, min_periods=12).min()     # 최근 6시간 최저값 대비  # ← 72칸 = 6시간
    tf = fc.time_features(gs.index)           # ← 시각·요일을 사인·코사인으로, 주말 여부
    for i, n in enumerate(["hs", "hc", "ds", "dc", "we"]):
        f[n] = tf[:, i]
    for j in range(n_spaces):
        f[f"sp{j}"] = 1.0 if j == si else 0.0 # ← 공간 원-핫 (내 공간 칸만 1)
    return f
```

def metrics(y, p) -> dict:
    cm = confusion_matrix(y, p, labels=[0, 1])        # ← 혼동 행렬 2×2
    tn, fp, fn, tp = cm.ravel()                       # ← 네 칸을 꺼냄
    return {"정확도": accuracy_score(y, p) * 100, "F1": f1_score(y, p) * 100, "macro-F1": f1_score(y, p, average="macro") * 100,
            "재현율": recall_score(y, p, zero_division=0) * 100, "정밀도": precision_score(y, p, zero_division=0) * 100,
            "빈 방→사용중 오판율": fp / max(tn + fp, 1) * 100, "cm": cm}   # ← 빈 방 중 사용중으로 잘못 본 비율
```

## 예상 질문 모음

**Q. 분류와 회귀의 차이는 무엇인가요?**
회귀는 "60분 뒤 CO₂ 가 몇 ppm 일까"처럼 숫자를 맞히는 것이고, 과제 3 이 회귀입니다. 분류는 "사람이 있나 없나"처럼 정해진 답 중 하나를 고르는 것이고, 과제 5 가 분류입니다. 분류 모델은 확률을 내고, 사용 여부는 0.5, 환기 경보는 0.91 이상이면 "예"로 판단했습니다.

**Q. HistGradientBoosting 은 어떤 모델인가요?**
예/아니오 질문으로 이루어진 작은 결정 트리를 수백 개 차례로 만들면서, 뒤의 나무가 앞의 나무 실수를 고치는 방식입니다. 숫자를 미리 구간으로 나눠 계산하기 때문에 빠르고, 표 형태 데이터에 강합니다. 사용 여부는 나무 300개, 환기 경보는 400개를 썼고, 적은 쪽을 놓치지 않도록 class_weight="balanced" 를 줬습니다.

**Q. 왜 사용 여부 입력에서 일정을 뺐나요?**
학습 정답을 일정으로 만들었기 때문입니다. 입력에도 일정을 넣으면 모델이 센서를 보지 않고 일정을 그대로 베껴, 학습 점수는 거의 100%가 되지만 실제와 다른 순간(노쇼, 예약 없는 사용)은 하나도 못 잡습니다. 반대로 환기 경보는 정답이 실제 CO₂ 에서 오기 때문에 앞으로의 일정 인원을 입력에 넣었습니다.

**Q. F1 85.8 은 좋은 결과인가요?**
단순 규칙(15분에 CO₂ 30ppm 이상 상승)의 F1 79.1 보다 높고, 일정 정답 자체(85.0)와 비슷하거나 약간 높습니다. 특히 재현율이 규칙 66.6 → 모델 84.9 로 크게 올라, 사람이 있는데 CO₂ 가 평탄한 경우도 잡습니다. 다만 퇴실 직후와 입실 직후에는 CO₂ 반응이 늦어 오류가 15~19.5%로 높습니다.

**Q. 환기 경보에서 왜 재현율을 더 중요하게 봤나요?**
환기를 놓치면 사람들이 졸리거나 두통이 생기지만, 헛경보는 창문을 한 번 여는 정도의 비용입니다. 그래서 검증 주에서 재현율 90%를 지키는 선에서 임계값을 정했고, 시험 주 재현율 97.4%, 정밀도 90.1%를 얻었습니다. 헛경보 체감은 같은 공간에 15분 안에 다시 울리지 않게 묶어서 줄입니다.

**Q. "항상 경보 없음"의 정확도가 97.1%인데 왜 나쁜가요?**
양성(곧 환기 필요)이 3.3%뿐이라 아무것도 안 해도 대부분 맞기 때문입니다. 하지만 정작 찾아야 할 양성을 하나도 못 잡아 재현율 0, macro-F1 49.3 입니다. 불균형한 문제에서는 정확도 대신 재현율·정밀도·macro-F1 을 봐야 합니다.

**Q. 내 데이터에서는 정답을 어떻게 만들었나요?**
직접 관찰 기록이 없어서 실습실 강단의 소음 센서(LAeq)를 대리 정답으로 썼습니다. 5분 최대 소음의 15분 중앙값이 34.5dB 이상이면 사용중으로 봤고, 빈 밤은 약 32dB, 수업 중은 35~37dB 였습니다. 소음은 모델 입력이 아니라서 정답으로 쓸 수 있고, 이 기준으로 모델 89.8%, 규칙 73.7%였습니다.

**Q. 라운지는 왜 따로 다뤘나요?**
라운지는 수업이나 예약 같은 일정이 없어서, 일정으로 만든 정답이 늘 "비어있음"입니다. 학습에 넣으면 모델이 "라운지는 항상 빈 방"이라고 배워 버립니다. 그래서 학습에서 빼고 처음 보는 공간으로 평가했고, 정확도 88.9%, F1 71.8 이었습니다.
