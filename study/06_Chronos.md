# 🤖 6. 과제 6 사전학습 모델 Chronos

남이 이미 아주 많은 시계열 데이터로 학습시켜 둔 모델(Chronos-Bolt)을, 우리 데이터로 추가 학습하지 않고 바로 CO₂ 예측에 써 본 과제입니다. 직접 학습한 GRU 와 정확도·불확실성·속도를 같은 시점에서 비교했습니다.

> 📖 읽는 순서: 1부(요약 → 비유 → 용어 → 사전학습 모델이란 → zero-shot → 예측 구간 → 합성 결과 → 실데이터 결과 → 보드 비용 → 채택 의견) → 2부(코드) → 자주 하는 실수 → 예상 질문

# 1부. 처음 보는 사람을 위한 설명

## 1. 한 문장으로 요약하면

> Chronos-Bolt tiny 를 추가 학습 없이(zero-shot) 썼더니, 합성 데이터에서는 60분 CO₂ 오차 40.1ppm 으로 직접 학습 GRU(14.8)는 물론 "현재값 유지"(38.4)보다도 나빴지만, 내 수집기 실데이터에서는 36.0ppm 으로 실데이터 학습 GRU(39.3)와 현재값 유지(42.0)보다 좋았습니다. 10~90% 예측 구간은 실제값을 약 80% 담아 불확실성을 정직하게 말했고, 보드에서 한 번에 약 90ms 라서 데이터가 적은 지금은 서비스 예측의 유력한 후보로 둡니다.

## 3. 용어 사전

| 용어 | 쉬운 뜻 | 이 과제에서는 |
| --- | --- | --- |
| 시계열 | 시간 순서대로 쌓인 숫자 | 5분 간격 CO₂ |

| 개선율 | 기준선보다 오차가 몇 % 줄었나 | 음수면 기준선보다 나쁨 |
| 추론 시간 | 예측 한 번에 걸리는 시간 | 보드에서 tiny 약 90ms, GRU 0.22ms |
| ONNX Runtime | 학습된 모델을 빠르게 실행하는 엔진 | 보드의 GRU 실행 방식 |

## 4. 사전학습(파운데이션) 시계열 모델이란

1. ChatGPT 같은 언어 모델(LLM)은 엄청난 양의 글을 읽고 "다음 단어"를 맞히도록 학습했습니다. 그래서 처음 보는 질문에도 그럴듯한 답을 합니다.
2. Chronos 는 같은 생각을 **숫자**에 적용했습니다. 전기 사용량, 날씨, 판매량 같은 아주 많은 시계열을 보고 "다음 숫자"를 맞히도록 미리 학습했습니다.
3. 그래서 우리 교실 CO₂ 를 한 번도 본 적이 없어도, 과거 곡선을 주면 "이런 모양 다음엔 보통 이렇게 간다"를 바탕으로 앞을 예측합니다.
4. 대신 Chronos 는 **CO₂ 과거값만** 봅니다. 시간대, 수업 일정, 온도·습도는 모릅니다. 이 점이 직접 학습한 GRU 와의 가장 큰 차이입니다.

## 5. zero-shot 이 왜 매력적인가

1. 직접 학습하려면 데이터가 몇 주는 쌓여야 합니다. 우리 실데이터는 처음에 하루치뿐이었습니다.
2. zero-shot 은 학습 단계가 아예 없습니다. 모델을 내려받아 과거값을 넣으면 바로 예측이 나옵니다.
3. 그래서 **데이터가 거의 없는 초기**나 **새로 센서를 단 공간**에 바로 쓸 수 있는 출발점이 됩니다.
4. 단점은 우리 공간의 특별한 사정(9시에 수업 시작, 쉬는 시간 급락)을 모른다는 것입니다.

## 6. 예측 구간과 적중률 (≈80%)

1. GRU 는 "60분 뒤 850ppm" 처럼 한 값만 냅니다.
2. Chronos 는 분위수 세 개를 냅니다. 10% 분위수(낮게 보면), 50%(가운데), 90%(높게 보면)입니다.
3. 10%~90% 사이가 **예측 구간**입니다. 모델이 정직하다면 실제값이 이 구간 안에 약 80% 들어와야 합니다.
4. 적중률이 80%보다 훨씬 낮으면 모델이 "자신만만하지만 틀림", 훨씬 높으면 "너무 넓게 말해서 쓸모없음"입니다.
5. MAE 계산에는 50% 분위수(중앙값)를 예측값으로 씁니다.

> 🎤 **Q. 적중률 80%가 왜 좋은 건가요?**
> 10%~90% 구간은 정의상 "실제값이 80% 확률로 이 안에 들어온다"는 뜻이라, 실제로 80% 들어오면 모델이 불확실성을 정직하게 말한 것입니다. 합성 데이터에서 tiny 24시간 컨텍스트의 적중률은 80.1~81.4%, 실데이터에서도 78~83%였습니다. GRU 는 한 값만 내기 때문에 이런 범위 정보를 줄 수 없고, 이것이 Chronos 의 장점입니다.

2. 합성 교실 CO₂ 는 수업 시작·쉬는 시간마다 톱니처럼 오르내립니다. 과거 곡선만 본 범용 모델은 "지금 오르는 중이니 계속 오른다"처럼 추세를 늘려 그리다가 쉬는 시간 급락을 못 맞힙니다.
3. 직접 학습 GRU 와의 차이 중 상당 부분은 **일정(미래 수업·예약)** 정보 때문입니다. 과거 곡선만으로는 "9시에 수업이 시작된다"를 알 수 없습니다. 일정 제외 GRU(19.9)와의 차이가 순수한 "우리 데이터로 학습한 효과"에 가깝습니다.
4. **과거를 길게 줄수록 좋아집니다**(2시간 49.8 → 24시간 40.1). 24시간을 주면 "어제 이 시간에 올랐다"는 하루 주기를 볼 수 있기 때문입니다.
5. tiny 와 small 의 차이가 거의 없습니다. 보드에 올린다면 더 작고 빠른 tiny 가 낫습니다.

## 8. 내 수집기 실데이터 결과 (2026-10-20 17:50 ~ 10-21 15:55, 22시간, 같은 230개 시점)

| 방법 | 5분 | 15분 | 30분 | 60분 CO₂ MAE (ppm) |
| --- | ---: | ---: | ---: | ---: |
| 현재값 유지 | 8.0 | 15.1 | 24.9 | 42.0 |
| 실데이터 학습 GRU (교육장 9/27~ 데이터로 학습) | 8.5 | 15.2 | 23.5 | 39.3 |
| **Chronos-Bolt tiny (학습 없음, 과거 최대 24시간)** | 10.0 | 15.0 | **22.1** | **36.0** |
| 10~90% 구간 적중률 (Chronos, %) | 82 | 83 | 82 | 78 |

해석:
1. **합성과 결과가 뒤집혔습니다.** 합성에서는 Chronos 가 가장 나빴지만, 실제 10월 교실에서는 30·60분에서 Chronos 가 가장 좋습니다.
2. 실제 교실 CO₂ 는 비교적 완만하게 오르내립니다. 범용 모델은 "완만한 추세 이어 그리기"에 강하고, 합성 데이터의 급격한 쉬는 시간 급락에는 약합니다.
3. 5분 앞은 Chronos(10.0)가 오히려 가장 나쁩니다. 아주 가까운 미래는 "지금 값" 자체가 가장 좋은 힌트라 현재값 유지(8.0)가 강합니다.
4. 예측 구간은 실데이터에서도 78~83%로 정직합니다.
5. 다만 **22시간·230개 시점은 표본이 작습니다.** 데이터가 더 쌓이면 다시 비교해야 합니다.

> 🎤 **Q. 합성에서는 꼴찌였는데 실데이터에서는 1등인 이유는?**
> 합성 데이터는 수업 시작과 쉬는 시간마다 CO₂ 가 톱니처럼 급하게 오르내리게 만들어졌고, Chronos 는 이런 급락을 예상하지 못해 60분 오차 40.1ppm 으로 현재값 유지(38.4)보다도 나빴습니다. 실제 10월 교실은 CO₂ 가 완만하게 움직여서, 추세를 자연스럽게 이어 그리는 범용 모델이 잘 맞았고 36.0ppm 으로 GRU(39.3)보다 좋았습니다. 즉 어떤 모델이 좋은지는 데이터의 모양에 달려 있고, 합성 결과만 믿으면 안 된다는 것을 보여 줍니다.

## 9. 비용: 보드에서 얼마나 빠른가

MacBook CPU (256개 묶음, 샘플당): tiny 24시간 컨텍스트 0.4ms, small 24시간 1.49ms.

**보드 (Jetson Orin Nano Super, CPU)** — `tools/bench.py`, 워밍업 50회 후 500회:

| 모델 | 배치 | 평균 ms | p95 ms | 메모리 증가 |
| --- | ---: | ---: | ---: | ---: |
| chronos-bolt-tiny (과거 24시간) | 1 | 91.9 | 106.0 | 약 68MB |
| chronos-bolt-tiny (과거 24시간) | 4 | 88.6 | 99.1 | |
| 직접 학습 GRU (ONNX Runtime) | 1 | 0.22 | 0.22 | 수 MB |

- Chronos tiny 는 한 번에 약 0.09초입니다. 서비스는 1분마다 돌기 때문에 충분히 빠릅니다. 공간 3개를 매분 예측해도 0.3초 수준입니다.
- 하지만 GRU 보다 약 400배 느리고, 메모리도 더 씁니다. 같은 보드에 로컬 LLM 도 올려야 하므로 이 부담을 따져야 합니다.
- p95 는 "100번 중 느린 5번을 뺀 최댓값"입니다. 가끔 느려지는 꼬리 지연을 보기 위해 평균과 함께 봤습니다.

## 10. 채택 의견

1. **처음 의견 (합성 결과만 보고)**: 일정 정보를 쓰는 GRU 보다 정확도가 낮고, 크고 느리므로 상시 서비스 기본 모델로는 채택하지 않고, 데이터가 부족한 새 공간용 예비 모델로만 둡니다.
2. **수정 의견 (실데이터 결과 반영)**: 학습 데이터가 거의 없는 지금(내 데이터 하루치)은 **Chronos-Bolt tiny 를 서비스 예측의 유력한 후보**로 봅니다. 보드에서 약 90ms·+68MB 라 감당할 수 있습니다.
3. **조건**: 표본이 작으므로 데이터가 3주 쌓이면 직접 학습 모델과 다시 비교해 정합니다. 일정 자료가 연결되면 일정을 쓰는 직접 학습 모델이 다시 앞설 가능성이 큽니다(합성 실험 근거: 일정 포함 GRU 14.8 vs 일정 제외 19.9).
4. 덤으로 Chronos 의 예측 구간(약 80% 적중)은 "얼마나 확실한지"를 운영자에게 보여 줄 수 있는 장점입니다.

> 🎤 **Q. 그래서 Chronos 를 쓰자는 건가요, 말자는 건가요?**

## 3. Chronos zero-shot 예측 — `inference/task6_pretrained.py`

```python
    for mid in args.models:
        pipe = BaseChronosPipeline.from_pretrained(mid, device_map="cpu", torch_dtype=torch.float32)   # ← 사전학습 모델을 내려받아 CPU 에 올림 (학습 없음)
        short = mid.split("/")[-1]
        for L in args.contexts:                                         # ← 과거 2·6·24시간 각각
            ctx = []
            for sp, t in zip(te["space"], te["time"]):
                i = pos[t]
                s = grid[(sp, "co2")].to_numpy()[max(0, i - L + 1):i + 1]   # ← 이 시점까지 과거 L칸 CO₂ 만 꺼냄
                s = pd.Series(s).interpolate(limit_direction="both").to_numpy()   # ← 빈 칸은 앞뒤 값으로 메움
                ctx.append(torch.tensor(s, dtype=torch.float32))
            t1 = time.time()
            qs = []
            for b in range(0, n, 256):                                  # ← 256개씩 묶어서
                q, _ = pipe.predict_quantiles(ctx[b:b + 256], prediction_length=12, quantile_levels=[0.1, 0.5, 0.9])   # ← 12칸(60분) 앞까지 10%·50%·90% 분위수
                qs.append(q.numpy())
            q = np.concatenate(qs)                  # [N,12,3]          # ← 시점 N개 × 12칸 × 분위수 3개
            timing[f"{short} ctx{L}"] = (time.time() - t1) / n * 1000   # ← 샘플당 걸린 시간(ms)
            add(f"{short} (과거 {L * 5 // 60}시간)", q[:, :, 1])        # ← 50% 분위수(중앙값)를 예측값으로 MAE 계산
            inside = (true >= q[:, :, 0]) & (true <= q[:, :, 2])        # ← 실제값이 10%~90% 사이에 들었나
            cover_rows.append({"model": f"{short} (과거 {L * 5 // 60}시간)", **{h: float(inside[:, k].mean() * 100) for h, k in HZ.items()}})   # ← 적중률(%)
        del pipe                                                        # ← 메모리 비우기
```

## 예상 질문 모음

**Q. 사전학습 모델(파운데이션 모델)이 무엇인가요?**
남이 아주 많은 데이터로 미리 학습시켜 둔 범용 모델입니다. ChatGPT 가 많은 글을 읽고 다음 단어를 맞히듯, Chronos 는 많은 시계열을 보고 다음 숫자를 맞히도록 학습되었습니다. 그래서 우리 교실 CO₂ 를 처음 봐도 과거 곡선만 주면 바로 예측할 수 있습니다.

**Q. zero-shot 은 무슨 뜻인가요?**
내 데이터로 추가 학습을 한 번도 하지 않고 바로 쓰는 것입니다. 이번 과제에서 Chronos 는 학습 단계 없이 `predict_quantiles` 만 호출했습니다. 데이터가 하루치뿐인 초기나 새 공간에 바로 쓸 수 있다는 것이 장점입니다.

**Q. Chronos 는 어떤 정보를 보고 예측하나요?**
CO₂ 과거값만 봅니다. 시간대, 수업 일정, 온도·습도는 모릅니다. 직접 학습 GRU 는 일정과 시간대를 함께 보기 때문에 합성 데이터에서 60분 14.8ppm 으로 훨씬 정확했고, 일정을 빼면 19.9ppm 이었습니다.

**Q. 합성 데이터 결과를 숫자로 말해 보세요.**
1,108개 시점에서 60분 CO₂ 오차는 GRU 14.8, 현재값 유지 38.4, 가장 좋은 Chronos(tiny, 과거 24시간) 40.1ppm 이었습니다. 즉 Chronos 는 현재값 유지보다도 4.3% 나빴습니다. 과거를 2시간에서 24시간으로 늘리면 49.8 → 40.1ppm 으로 좋아졌습니다.

**Q. 실데이터 결과는 어떤가요?**
내 수집기 22시간, 같은 230개 시점에서 60분 CO₂ 오차는 Chronos tiny 36.0, 실데이터 학습 GRU 39.3, 현재값 유지 42.0ppm 으로 Chronos 가 가장 좋았습니다. 30분에서도 22.1ppm 으로 가장 좋았습니다. 실제 교실 CO₂ 가 완만하게 움직여 범용 모델의 추세 이어 그리기가 잘 맞은 것으로 봅니다.

**Q. 예측 구간 적중률은 무엇이고 결과는?**
10%~90% 분위수 사이에 실제값이 들어온 비율로, 정직한 모델이면 80%여야 합니다. 합성에서 tiny 24시간은 80.1~81.4%, 실데이터에서는 78~83%로 거의 80%였습니다. GRU 는 한 값만 내서 이런 정보가 없기 때문에 Chronos 의 장점입니다.

**Q. tiny 와 small 중 왜 tiny 인가요?**
합성 데이터에서 60분 오차가 tiny 40.1, small 41.6ppm 으로 거의 같았습니다. tiny 가 더 작고 빨라서(MacBook 샘플당 0.4ms vs 1.49ms) 보드에 올리기 좋습니다. 같은 보드에 로컬 LLM 도 올려야 하므로 작은 모델이 유리합니다.

**Q. 보드에서 너무 느리지 않나요?**
보드에서 tiny 는 한 번에 평균 91.9ms, p95 106.0ms, 메모리 약 +68MB 였습니다. 서비스는 1분마다 돌기 때문에 공간 3개를 예측해도 0.3초 수준이라 충분합니다. 다만 ONNX GRU(0.22ms)보다 약 400배 느리기 때문에 보드 자원이 빠듯하면 부담이 될 수 있습니다.
