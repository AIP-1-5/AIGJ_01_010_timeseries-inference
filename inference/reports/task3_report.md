# 과제 3. 60분 예측

> 측정 조건: 합성 데이터 5주 (자체 생성기, seed 7) · 학습 1~3주 / 검증 4주 / 시험 5주 (고장 구간 제외) · 5분 간격 · 과거 120분 입력 · 시험 샘플 6,653개 · CPU 학습 (MacBook)

## 1. 입력·출력 설계
- 과거 2시간(24칸): CO₂·온도·습도(공간별 정규화) + 시간대·요일(sin/cos) + 그 시점 일정 인원
- 공간 원-핫 (어느 공간인지), 앞으로 60분의 **일정 인원(수업 시간표·회의실 예약)** — 미래에도 미리 아는 정보
- 출력: 60분을 **한 번에** 12칸 출력 (한 칸씩 반복 예측하면 오차가 누적됨)
- 출력은 '지금 값 대비 변화량' → 기본값이 '현재값 유지'가 되어 학습이 안정적

## 6. 결론
- 가장 좋은 모델: **LSTM** — 60분 CO₂ 오차 14.9ppm, '현재값 유지'(40.9ppm) 대비 **64% 감소** (✅ 목표 30% 달성)
- **일정 정보의 가치**: 일정을 넣으면 60분 CO₂ 오차가 5.4ppm 줄어든다 (GRU 일정 제외 20.4 → 포함 15.0ppm).
- 공간별로는 **강의실1** 가 가장 어렵다(60분 19.0ppm). 인원이 가장 많아(정원 30명) 수업 시작·쉬는 시간마다 CO₂ 가 수백 ppm씩 오르내리고, 쉬는 시간 창문 개방 여부도 날마다 다르기 때문이다.
- 일정 정보 효과가 가장 큰 공간: **회의실** (60분 오차 31.4 → 17.5ppm). 과거 센서값에는 '곧 누가 들어온다'는 정보가 없어서, 수업 시작·회의 예약을 미리 알면 상승 시점을 맞힐 수 있다. 다만 노쇼·연장·예약 없는 사용처럼 일정과 실제가 어긋나는 경우는 일정을 넣어도 맞히지 못한다.
- 오차가 큰 순간은 수업 시작·쉬는 시간(창문 개방)·회의 시작처럼 재실 인원이 급변하는 시점이다. 일정은 '계획'만 알려 주므로 지각·결석·연장으로 생기는 차이는 여전히 맞히기 어렵다.
- 온도는 냉방이 설정 온도로 묶어 두어 변화가 작아 모든 방법의 오차가 작다. 대신 냉방 정지 같은 고장 때 크게 벗어난다(과제 4).
- 실데이터에는 일정 자료가 없어, 서비스(과제 8)에는 '일정 제외' 모델을 쓰거나 일정 자료를 받아 연결해야 한다.
