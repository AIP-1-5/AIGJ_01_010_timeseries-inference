# '생각해 볼 점' 보충 답변 (원본 과제 문서 기준, 보고서에 답이 없거나 얕았던 것)

## 과제 2. 고장이 섞인 구간은 학습에 넣어야 할까, 평가에서는?
- **학습에서는 뺀다.** 예측 모델은 '정상일 때 다음 값'을 배워야 한다. 값 고정·영점 틀어짐 구간을 넣으면 모델이 고장 모양을 정상으로 외워, 나중에 같은 고장이 와도 예측 오차가 작아져 과제 4의 예측 오차 탐지기가 고장을 못 잡는다. 오토인코더도 정상만으로 학습해야 고장을 '처음 보는 모양'으로 알아본다.
- **예측 성능 평가에서도 뺀다** (`task3_forecast.py` 의 `excl`: 고장 시작 2시간 전 ~ 끝 60분 뒤 제외). 고장 구간을 넣으면 '센서가 틀린 값'을 맞히는 능력을 재게 되어 모델 비교가 공정하지 않다.
- **이상 탐지 평가에서는 반드시 넣는다.** 탐지율·지연은 고장 구간으로만 잴 수 있고, 헛경보율은 나머지 정상 구간으로 잰다.
- 실데이터는 고장 정답이 없다. 지금은 정제 단계에서 범위 밖 값만 지우고 있다(과제 2). 더 나아가려면 규칙 탐지기가 표시한 구간(튄 값·값 고정)도 학습에서 빼고, 평가 표에 '규칙 경보 구간 제외'를 측정 조건으로 적는 것이 맞다(다음 개선).

## 과제 8. 막 시작된 5분 칸(아직 1~2분치만 있음)을 써도 될까?
- **쓰지 않는다.** 5분 칸 값은 그 5분 동안 들어온 측정의 평균이다. 1~2분치로 만든 칸은
  1. 학습 데이터의 칸(5분이 다 찬 평균)과 성격이 달라 모델 입력 분포가 어긋나고,
  2. 센서 주기가 1·2·10분으로 제각각이라 어떤 센서는 아직 한 번도 안 들어와 공간 평균이 일부 센서로만 계산되며(실습실은 9대 중 몇 대만),
  3. 몇 초 뒤 값이 바뀌므로 같은 시각 예측이 매분 출렁인다.
- 그래서 서비스는 '마지막으로 다 찬 5분 칸'까지만 쓰고(`time` = 그 칸의 시작), 예측 기준 시각도 그 칸이다. 대가는 최대 5분 늦은 반영이지만, 60분 예측에서는 문제가 되지 않는다.

## 과제 8. 학습과 서비스의 전처리가 다르면 무슨 일이 생기나?
- 모델은 학습 때 본 입력 분포만 안다. 예를 들어 서비스에서 기기별 평균을 먼저 하지 않고 바로 공간 평균을 내면, 주기가 다른 센서가 번갈아 들어오며 값이 톱니처럼 흔들린다(과제 2에서 실제로 확인). 모델은 이것을 '급변'으로 읽어 과장된 예측과 헛경보를 낸다.
- 중복 제거를 빼면 같은 값이 5분 간격으로 두 번 들어가고(게이트웨이 시계 4분 55초 차이), 정규화 통계를 다르게 쓰면 모든 값이 일정하게 밀린다.
- 이런 '학습-서비스 어긋남'은 오류 메시지 없이 성능만 조용히 떨어뜨려서 찾기 어렵다. 그래서 맥(학습)과 보드(서비스)가 **같은 파일 `tsinf/prep.py`** 를 쓰고, 서비스가 스스로 채점해(자기 채점, `/monitor`) 성능이 떨어지면 알린다.

## 과제 8. 다음 주 로컬 LLM이 이 서비스를 '도구'로 쓰려면 결과에 무엇이 더 있어야 할까?
1. **기계가 읽는 설명서**: 엔드포인트·인자·응답 필드를 적은 스키마(OpenAPI 또는 함수 호출용 JSON 스키마). LLM 은 이걸 보고 어떤 질문에 어떤 API 를 부를지 정한다. 지금은 `docs/interface.md`(사람용)만 있다.
2. **단위와 기준 시각을 값마다**: `co2: 812 (ppm, 10:35 기준 30분 뒤)` 처럼. 지금 JSON 은 `units`·`base_time` 이 따로 있어 LLM 이 섞어 쓸 수 있다.
3. **불확실성**: 예측 구간(예: 10~90%)이나 '이 공간 최근 60분 예측 평균 오차 31ppm'(자기 채점 결과 `monitor` 를 이미 넣음). LLM 이 "확실하지 않다"고 말할 근거가 된다.
4. **근거와 원인**: 경보마다 왜 울렸는지(규칙 이름, z 점수, 비교 대상)와 권장 조치. 형식 문서의 kind 표를 응답에 함께 실으면 LLM 이 설명을 지어내지 않는다.
5. **한 줄 요약 문장**: `"summary": "회의실, 25분 뒤 1,000ppm 초과 예상. 환기 권장."` — 작은 LLM 도 그대로 전달할 수 있다.
6. **신선도·유효성**: `data_age_sec`, `forecast.available`, `reason` 은 이미 있다. LLM 이 오래된 값을 최신처럼 말하지 않게 한다.
7. **질문형 엔드포인트**: "몇 분 뒤 1,000 넘나?", "지금 비어 있나?"처럼 자주 묻는 질문을 바로 답하는 API(`/spaces/<slug>/forecast?minutes=` 는 이미 있음).
